Every redaction is decided by a DFA

A deterministic finite automaton (DFA) is a fixed table of states and transitions. Here, four of them read each token one character at a time and accept or reject it as an email, phone number or API key. Accepted tokens are replaced in place.

How it works

          
    
            
  1. 
              
    Split into tokens
    
              
    The text is cut at spaces, commas, quotes and brackets. Each token keeps its position in the original text.
    
            
    2. 
            
  2. 
              
    Run the right DFA
    
              
    A known key prefix (sk-, ghp_) goes to the vendor key DFA, an @ to the email DFA, 20 or more characters to the generic key DFA, and a leading + or digits to the phone DFA. The DFA reads the token one character at a time through its transition table.
    
            
    3. 
            
  3. 
              
    Accept, then replace
    
              
    If the DFA ends in its accepting state q1 the token becomes a tag like [EMAIL_01]. Any missing transition means the dead state q_d, and the token is left alone.
    
            
    4. 
          

          

            NAME=value pairs are checked on the value too, so API_KEY=sk-live-... is caught.
            Known limits: phone numbers with spaces or parentheses, and emails inside URLs such as
            https://user@host.com, are not detected.
          

        

      

    


    

      

        Runs on 127.0.0.1 only. Text is processed in memory and never stored.
